# BPMT Lite v1.4.1 Implementation Plan

> 执行顺序固定为：`Nginx -> 分层 -> 数据库操作 -> 文档 -> issue #9`。  
> 本计划基于：`docs/superpowers/specs/2026-05-02-bpmt-lite-v1.4.1-design.md`。

## 0. 执行前约束

- 保持 Java 8 / Maven 3 / Tomcat 7 / MariaDB，不升级技术栈。
- API 路径统一为 `/api/v1/<module>/*`，不做 v1.4.0 路径兼容。
- compose 内服务端口必须唯一，不允许多个服务复用同一容器监听端口。
- 发布前必须同步文档与 GitHub issue 收口状态。

---

## 1. Nginx 单入口（第 1 阶段）

**目标：** 新增 `nginx` 作为唯一外部入口；`web` 监听 `8080`，`api` 监听 `8081`，容器内端口不重复。

**涉及文件（预期）：**
- `docker-compose.yml`
- `docker/nginx/nginx.conf`（新增）
- `README.md`
- `docs/maintenance.md`

- [ ] Step 1: 在 compose 中新增 `nginx` 服务，映射宿主机 `80:80`。
- [ ] Step 2: 将 `api` 容器监听端口调整为 `8081`（容器内），并移除任何与 `web` 的端口冲突。
- [ ] Step 3: 配置 `nginx` 路由：
  - `/`、`/ueditor/` -> `web:8080`
  - `/api/` -> `api:8081`
- [ ] Step 4: 验证路由与健康检查：
  - `curl -fsSI http://127.0.0.1/`
  - `curl -fsSI http://127.0.0.1/ueditor/`
  - `curl -fsSI http://127.0.0.1/api/openapi.json`
  - `curl -fsSI http://127.0.0.1/api/docs/`

## 3. 数据库操作模块（第 3 阶段）

**目标：** 暴露与 `DbHelper` 同名的 4 个受控接口：`query`、`exec`、`save`、`find`。

**接口清单：**
- `POST /api/v1/database-operations/query`
- `POST /api/v1/database-operations/exec`
- `POST /api/v1/database-operations/save`
- `POST /api/v1/database-operations/find`

**行为约束：**
- `query/find` 仅允许 `SELECT`
- `save` 仅允许 `INSERT`
- `exec` 仅允许受控 DML（如 `UPDATE/DELETE`），拒绝高危语句
- 统一走 HMAC 认证与 `success/data/error`

**涉及文件（预期）：**
- `platform/src/main/java/com/riversoft/platform/db/DbHelper.java`（只读依赖，不改或最小改）
- `api/src/main/java/com/riversoft/api/modules/database_operations/**`
- `api/src/main/webapp/openapi.json`
- `api/src/test/java/com/riversoft/api/modules/database_operations/**`

- [ ] Step 1: 实现 `database-operations` controller/service/dto。
- [ ] Step 2: 映射 `DbHelper.query/exec/save/find` 语义。
- [ ] Step 3: 增加配置开关并接入：
  - `BPMT_API_DBOPS_EXECUTE_ENABLED`（默认 `false`）
  - `BPMT_API_DBOPS_MAX_ROWS`
- [ ] Step 4: 补齐单测：
  - 正向路径
  - 非法 SQL 类型拒绝
  - 认证失败与错误码结构
- [ ] Step 5: 执行 `scripts/smoke-api.sh` 并扩展覆盖 dbops 场景。

## 7. 回滚策略

- 若 Nginx 切换失败：移除 `nginx` 服务并恢复 `web/api` 直连模式。
- 若 API 重构失败：回退到 `v1.4.0` tag 与对应镜像。
- 若 dbops 风险过高：关闭 `BPMT_API_DBOPS_EXECUTE_ENABLED` 并保留只读路径。
