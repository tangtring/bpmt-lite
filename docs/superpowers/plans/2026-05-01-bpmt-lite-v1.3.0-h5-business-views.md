# bpmt-lite v1.3.0 H5 Business Views Implementation Plan

> 2026-05-01 strategy update: the steps that add or expand the `bpmt-h5` component layer and rework business-view structure are stopped. v1.3.0 now uses a conservative bug-fix strategy: preserve the original AmazeUI H5 pages and only fix blockers, missing resources, route selection, and `_action_mode=h5` propagation. Current execution and acceptance follow `docs/v1.3.0/h5-acceptance.md` and `AGENTS.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rework the mobile H5 experience for BPMT business views so `dyn`, `flowbasic`, `rep_list`, `note`, and compatibility `viewer` URLs can be validated one by one on the full `bpmt` database.

**Architecture:** Keep Java 8, Maven 3, Tomcat 7, JSP/JSTL, existing Action routing, and dynamic business configuration unchanged. Improve the existing `/h5/**` JSP templates and the local `bpmt-h5` CSS/JS compatibility layer, then validate with concrete URLs from `VW_URL`.

**Tech Stack:** Java 8, Maven 3, Tomcat 7, JSP/JSTL, legacy Action framework, jQuery 1.x, Docker Compose, MariaDB.

- [ ] **Step 2: Add JS helpers**

```javascript
window.BpmtH5 = window.BpmtH5 || {};
window.BpmtH5.confirm = function(message, onOk) {
	if (window.Wxui && typeof window.Wxui.confirm === "function") {
		window.Wxui.confirm(message, onOk);
		return;
	}
	if (window.confirm(message) && typeof onOk === "function") {
		onOk();
	}
};
window.BpmtH5.notice = function(message) {
	if (window.Wxui && typeof window.Wxui.alert === "function") {
		window.Wxui.alert(message);
		return;
	}
	window.alert(message);
};
```

Expected: H5 pages can call confirmation and notice without assuming AmazeUI modal plugins exist.
