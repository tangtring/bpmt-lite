# bpmt-lite v1.3.0 H5 业务视图设计

## 背景

`bpmt-lite` v1.2.0 已完成 Docker 化、初始化数据库、字体、日志目录等发布工作。v1.3.0 转向移动端 H5 可用性。

前一阶段已经修复登录、首页、菜单、首页面板和本地 H5 静态资源加载问题。用户进一步确认：v1.3.0 的重点不是后台管理模块的“功能设置”域，而是动态表、工作流、报表等业务视图在移动端的完整使用体验。

本设计以 `com.riversoft.platform.web.view.annotation.View` 标注的视图类型作为边界。

## 视图类型

完整 `bpmt` 数据库中，`VW_URL` 当前包含以下业务视图：

| `VIEW_CLASS` | 数量 | 运行入口 |
| --- | ---: | --- |
| `dyn` | 52 | `/dyn/A{VIEW_KEY}Action/...`，`VIEW_KEY` 中 `-` 转为 `$` |
| `flowbasic` | 35 | `/flow/view/A{VIEW_KEY}Action/...`，`VIEW_KEY` 中 `-` 转为 `$` |
| `rep_list` | 21 | `/report/A{VIEW_KEY}Action/...`，`VIEW_KEY` 中 `-` 转为 `$` |
| `note` | 1 | `/{VIEW_KEY}.view` |
| `viewer` | 32 | `/{VIEW_KEY}.view` |

## 目标

v1.3.0 目标调整为：恢复并重构主要业务视图的移动端交互方式，使完整库中的典型业务 URL 可以逐条验收。

必达目标：

1. H5 登录、首页、菜单、首页面板继续可用。
2. `dyn` 动态表完成列表、查询、详情、新建、编辑、删除闭环。
3. `flowbasic` 工作流完成入口、列表、详情、表单和普通办理主路径。
4. `rep_list` 报表完成列表、查询、详情和下载兼容。
5. `note` 公告完成列表和详情。
6. `viewer` 做兼容降级，保证 HTML/消息可读，下载类不破。
7. 每一类视图都列出具体业务 URL 逐条验收。

## 非目标

v1.3.0 不做以下事项：

- 不适配后台管理模块的“功能设置”域。
- 不移动化流程设计器、视图设计器、字段配置器、权限配置器等后台配置页面。
- 不把 H5 改造成 SPA。
- 不引入 Node、npm、Webpack、Vite。
- 不升级 Java、Maven、Tomcat、Spring、Hibernate。
- 不一次性删除 AmazeUI。
- 不重写权限、菜单、流程、动态表、报表的数据模型。

## 架构策略

保持原有 Java Action/JSP 渲染架构：

- `ActionMode(Mode.FIT)` 和 `_action_mode=h5` 继续负责 H5 分流。
- `Actions.Util.getPagePath()` 继续选择 `/h5/**` JSP。
- 业务 Action、Service、动态配置模型不改语义。
- H5 资源继续通过本地 JSP 直接加载，不引入构建链。

移动端体验通过本地轻量组件层修复：

- `platform/src/main/webapp/h5/assets/bpmt-h5.css`
- `platform/src/main/webapp/h5/assets/bpmt-h5.js`

该层只负责移动端布局、列表、详情、表单、操作反馈和兼容兜底，不承担业务模型重写。

## 模块设计

### 动态表 `dyn`

入口来自 `DynViewAction` 和 `BaseDynamicTableCRUDAction`。

H5 页面：

- `platform/src/main/webapp/h5/dyn/main.jsp`
- `platform/src/main/webapp/h5/dyn/list.jsp`
- `platform/src/main/webapp/h5/dyn/detail.jsp`
- `platform/src/main/webapp/h5/dyn/form.jsp`

移动端设计：

- 列表改为卡片化字段摘要，不依赖桌面宽表。
- 查询区默认收起或纵向排列。
- 详情按字段块展示。
- 表单控件保持原有 tag 输出，但用 CSS/JS 处理移动端宽度、点击区域、提示。
- 删除、保存、错误反馈通过 `bpmt-h5.js` 兜底，不依赖外部弹窗库。

### 工作流 `flowbasic`

入口来自 `FlowBasicViewAction` 和 `BaseFlowBasicAction`。

H5 页面：

- `platform/src/main/webapp/h5/flow/view/main.jsp`
- `platform/src/main/webapp/h5/flow/view/portal_person.jsp`
- `platform/src/main/webapp/h5/flow/view/portal_all.jsp`
- `platform/src/main/webapp/h5/flow/view/list.jsp`
- `platform/src/main/webapp/h5/flow/view/detail.jsp`
- `platform/src/main/webapp/h5/flow/view/form.jsp`

移动端设计：

- `main` 页面突出个人待办、全部列表、发起入口。
- 列表以流程单据卡片展示。
- 详情和表单纵向展示字段。
- 办理意见、按钮区固定为清晰的移动端操作区。
- 保留原有流程动作接口，不改变流转语义。

### 报表 `rep_list`

入口来自 `ReportListViewAction` 和 `BaseReportListAction`。

H5 页面：

- `platform/src/main/webapp/h5/report/main.jsp`
- `platform/src/main/webapp/h5/report/list.jsp`
- `platform/src/main/webapp/h5/report/detail.jsp`

移动端设计：

- 列表字段摘要化，避免横向表格撑破。
- 查询条件纵向排列。
- 详情页按字段块展示。
- 下载动作保留原链接，移动端不支持预览时不包装成错误页面。

### 公告 `note`

入口来自 `NoteViewAction`。

H5 页面：

- `platform/src/main/webapp/h5/view/note/NoteViewAction/list.jsp`
- `platform/src/main/webapp/h5/view/note/NoteViewAction/detail.jsp`

移动端设计：

- `.view` 路由必须在 H5 下正确进入公告列表。
- 公告标题、发布时间、正文内容在移动端可读。
- 保持 `LoginType.USER` 和 `LoginType.NONE` 的兼容行为。

### Viewer `viewer`

入口来自 `ViewerViewAction`。

Viewer 是输出型视图，结果可能是 HTML、TEXT、MSG、WORD、EXCEL、PDF。

移动端设计：

- HTML/TEXT/MSG 用 H5 轻包装保证可读。
- WORD/EXCEL/PDF 下载类保持原响应，不强制移动端预览。
- 本轮不建立完整 Viewer 移动组件体系。

## 逐 URL 验收矩阵

详细 URL 和验收动作以 `docs/v1.3.0/h5-acceptance.md` 为准。该文件使用完整 `bpmt` 数据库中的 `VW_URL` 生成候选，并手工挑选覆盖不同业务域和页面能力的样本。

本设计的验收原则：

- 每类视图至少 1 条主 URL 必须通过移动端浏览器验收。
- `dyn` 和 `flowbasic` 必须各选择 1 条高频主路径做写入冒烟。
- `rep_list` 必须覆盖至少 1 条横向字段较多的报表。
- `viewer` 必须同时覆盖 HTML 类和下载类。

## 验证方式

基础命令：

```bash
scripts/verify-repo.sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-1.8.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
mvn -s settings.local.xml -DskipTests compile
docker compose config
```

浏览器验收：

- 使用完整 `bpmt` 数据库。
- 使用移动视口。
- 登录 `admin/admin`。
- 对 `docs/v1.3.0/h5-acceptance.md` 中 URL 逐条记录 HTTP 状态、控制台错误、页面可读性和操作结果。
