# bpmt-lite v1.5.1 issue #10 修复设计

## 1. 背景

`bpmt-lite` 当前发布基线是 `v1.5.0`。`v1.5.0` 已新增外部系统 OAuth 登录能力，并保留 `v1.4.1` 的独立 `api` 容器、`nginx` 单入口和数据库操作模块能力。

GitHub issue `#10` 报告：访问完整库环境中的 `/flow/CommonFlowAction/taskList.shtml` 后，点击任务列表的“查看”或“处理”按钮会跳到异常链接，例如：

```text
/kzFiJIdJL9X.view?_params={form:true,pdKey:%27%27}&_TASK_ID=6dc08a39-463d-11f1-a2e6-9e6cbc177202&_ORD_ID=null&_zone=win_6&_form=null
```

该问题曾在 `v1.4.1` 验收文档中记录为已修复，但 issue 后续被重开，并明确反馈 `1.4.1` 没有真正修复。因此 `v1.5.1` 必须以完整库真实运行复现和浏览器实点验收为准，不能只复用旧验收结论。

## 2. 版本定位

`v1.5.1` 是基于 `v1.5.0` 的补丁版本。

本版本保留并回归验证 `v1.5.0` 已发布的 OAuth 登录能力，但不新增 OAuth 端点、不修改 OAuth 协议、不实现 `userid + thirdpartKey` 独立权限校验 API。

本版本新增修复范围只包含 GitHub issue `#10` 的工作流待办跳转 bug。

## 3. 目标

- 修复完整库 `bpmt` 中 `/flow/CommonFlowAction/taskList.shtml` 点击“查看”或“处理”后 `_ORD_ID=null` 的问题。
- 确保待办任务从 `taskId` 能稳定进入对应工作流查看或办理页面。
- 对真实完整库数据做浏览器实点验收，并记录可复核的网络请求和最终页面状态。
- 同步补充 `v1.5.1` 发布文档、验收文档、README、脚本默认版本和镜像 tag。
- 发布 `1.5.1` Web/API 镜像，同步 `latest`，创建 `v1.5.1` tag 和 GitHub Release。
- 在完整库验收通过后关闭 GitHub issue `#10`，并写明真实复测结果。

## 4. 非目标

- 不新增 OAuth 功能。
- 不改 OAuth JSON 响应格式。
- 不新增 `bpmt-api` 业务接口。
- 不改动态表结构 API 或数据库操作 API 的行为。
- 不做 H5、动态表、流程视图的大范围重构。
- 不调整数据库结构，除非真实复现证明完整库初始化数据本身缺失必要运行数据。
- 不以最小库 `bpmt_min` 的空待办或入口 smoke 代替 issue 验收。

## 5. 修复策略

### 5.1 复现优先

先使用完整库 `bpmt` 启动 `web + api + mariadb + nginx`，登录 `admin/admin`，访问：

```text
/flow/CommonFlowAction/taskList.shtml
```

浏览器实点“查看”和“处理”，记录：

- 实际 `taskId`。
- 对应 `processInstanceId`。
- 对应 `businessKey`。
- `CommonFlowAction` 跳转前后的 URL。
- `.view` 转发后的真实 Action URL。
- 最终页面 HTTP 状态和页面状态。

如果完整库中没有可用待办，必须通过现有业务流程创建一条可用待办后再验收，不能用空列表作为通过依据。

### 5.2 根因分支

围绕 `CommonFlowAction.form()`、`CommonFlowAction.detail()`、`ViewDirectFilter` 和相关 JSP 按以下分支定位：

1. 如果 `taskId -> processInstance.businessKey` 本身为空，确认是流程实例数据缺失还是旧流程兼容问题。只有在完整库真实数据需要时，才增加受控兜底来源，例如从 BPMT 业务订单上下文或流程历史关系解析 `ordId`。
2. 如果 `businessKey` 有值但跳转 URL 中变成 `null`，修 `CommonFlowAction` 中的 redirect 参数构造和空值防御。
3. 如果 `CommonFlowAction` 生成的 URL 正确，但经过 `.view` 后丢 query，修 `.view` 转发链路，确保原始 query 能透传到动态视图 Action。
4. 如果按钮触发路径不是预期的 `/flow/CommonFlowAction/form.shtml` 或 `/flow/CommonFlowAction/detail.shtml`，修 `task_list.jsp` 的调用入口和参数传递。

### 5.3 改动原则

改动必须保持窄范围，优先修改实际丢参数的最小位置。不得为了本 issue 新增通用工作流路由框架，也不得重写流程视图。

错误处理要显式：当任务不存在、流程实例不存在、业务主键为空且无法兜底时，应返回清晰业务错误，不能继续拼出 `_ORD_ID=null`。

## 6. 测试设计

### 6.1 单元或窄范围测试

至少覆盖：

- 给定有效 `_TASK_ID` 时，`CommonFlowAction.form()` 的 redirect URL 包含非空 `_TASK_ID` 和 `_ORD_ID`。
- 给定有效 `_TASK_ID` 时，`CommonFlowAction.detail()` 能进入对应查看路径。
- 当任务不存在时返回稳定业务错误，不生成异常 `.view` URL。
- 当流程实例业务主键为空且无法兜底时返回清晰错误，不输出 `_ORD_ID=null`。

如果根因在 `.view` query 透传，则补 `ViewDirectFilter` 或等价窄范围测试，确认原始 query 参数不会丢失。

### 6.2 完整库浏览器验收

使用完整库 `bpmt` 做主验收：

- 登录 `admin/admin`。
- 打开 `/flow/CommonFlowAction/taskList.shtml`。
- 点击“查看”，最终进入真实工作流查看页面。
- 点击“处理”，最终进入真实工作流办理页面。
- 网络请求中不出现 `_ORD_ID=null`。
- 网络请求中能看到真实 `_TASK_ID` 与 `_ORD_ID`。
- 页面不返回 `400` 或 `500`。

### 6.3 v1.5.0 基线回归

`v1.5.1` 必须继承 `v1.5.0` 基线，发布前回归：

- `/` 返回 `200`。
- `/ueditor/` 返回 `200`。
- `/api/docs/` 返回 `200`。
- `/api/openapi.json` 返回 `200`。
- `/oauth/authorize` 未登录时仍进入 BPMT 登录页，登录后可继续 OAuth authorize 基础流程。
- `bpmt-api` 不新增接口，但现有 API 文档和 smoke 仍通过。

最小库 `bpmt_min` 只用于启动、入口和 API smoke，不作为 issue `#10` 的主验收数据源。

## 7. 文档与发布

实现完成后必须同步更新：

- `README.md`：当前版本、默认镜像、Quick Start tag、OAuth 基线说明和 issue 修复说明。
- `docs/release-v1.5.1.md`：发布说明。
- `docs/v1.5.1/issue-10-acceptance.md`：完整库复现、根因、修复点和真实浏览器验收记录。
- `docs/maintenance.md`：如维护验收命令或基线版本有变化则同步。
- `scripts/install.sh`、`scripts/run.sh`、`scripts/init-db.sh`：默认 release tag 或数据库资源 URL。
- `docker-compose.yml`、Maven 版本和 API OpenAPI 版本号：切换到 `1.5.1`。

发布收口包括：

- 构建 `ghcr.io/wodenwang/bpmt-lite:1.5.1`。
- 构建 `ghcr.io/wodenwang/bpmt-lite-api:1.5.1`。
- 同步两个 `latest` tag。
- 创建 Git tag `v1.5.1`。
- 创建 GitHub Release。
- 完整库验收通过后关闭 issue `#10`。

## 8. 风险与约束

- `#10` 曾有误判记录，本次必须先复现再修复，不能用代码阅读替代真实验证。
- 完整库任务状态可能随验收过程变化。验收记录必须写明使用的任务、订单号、入口 URL 和最终页面。
- 如果现有完整库没有可用待办，应通过现有业务流程创建待办，不应直接手写流程运行表绕过平台逻辑。
- OAuth 是 `v1.5.0` 基线能力，`v1.5.1` 虽不新增 OAuth 功能，但必须确保该能力没有被工作流修复破坏。
- Docker 默认初始化仍遵守首次创建 `db/data` 才导入 SQL 的规则；完整库复测需要使用干净临时运行目录或明确重建数据目录。

## 9. 通过标准

`v1.5.1` 只有在以下条件全部满足后才能发布：

- issue `#10` 在完整库 `bpmt` 下可真实复现或有明确复现记录。
- 修复后浏览器实点“查看”和“处理”均通过。
- `_ORD_ID=null` 不再出现在待办跳转网络请求中。
- 单元或窄范围测试覆盖关键跳转和错误分支。
- 完整库主验收、最小库 smoke、API smoke、OAuth 基线 smoke 均通过。
- 文档、版本号、脚本默认 tag、镜像 tag、GitHub Release 与 `1.5.1` 对齐。
- issue `#10` 的关闭评论包含真实完整库复测结果。
