# bpmt-lite v1.6.1 微信生态第三方 OAuth 登录态传导设计

## 1. 背景与目标

`v1.6.1` 是基于 `v1.6.0` 的补丁版本。`v1.6.0` 已支持 HTTPS 入口、可信上游 TLS，以及 `v1.5.x` 的外部系统 OAuth 登录能力。

当前第三方系统作为 OAuth client 访问 BPMT `/oauth/authorize` 时，BPMT 会先校验 `client_id` 与 `redirect_uri`，再通过 `SessionManager.checkUserLogin()` 判断当前浏览器是否已有 BPMT 登录态。没有登录态时，现有流程会保存 `OAUTH_RETURN_URL` 并跳转普通 `/login.jsp`。

本版本要补齐微信生态下的登录态传导：当第三方系统在微信内发起 BPMT OAuth 登录，且当前没有 BPMT 登录态时，BPMT 不应显示普通登录页，而应按该第三方系统绑定的微信配置发起微信 OAuth 登录。微信登录成功后，BPMT 回到原始 authorize 请求，继续标准 OAuth Authorization Code 流程，最终回跳第三方 `redirect_uri?code=...&state=...`。

本机开发环境无法真实访问微信登录，因此本版本还必须提供可自动化验证的本机替身机制，证明微信登录态补齐后能继续签发第三方 OAuth code。

## 2. 范围

### 2.1 本版本包含

- 在外部系统 OAuth client 配置上增加微信登录绑定能力。
- 支持企业号/企业微信登录与服务号登录两类绑定。
- `/oauth/authorize` 在微信 UA、未登录、第三方启用微信登录绑定时，自动进入微信 OAuth 登录。
- 微信登录成功后回到原始 authorize 请求，再按现有第三方 OAuth 流程签发授权码。
- 未配置微信登录绑定的第三方系统保持 `v1.6.0` 行为。
- 本机单测和 smoke 通过 fake 微信 provider 验证完整登录态传导链路。
- README、维护文档、发布文档、验收文档和 `AGENTS.md` 同步更新。

### 2.2 本版本不包含

- 不新增第三方通知接口。
- 不改变第三方 OAuth client 的标准接入方式。
- 不实现 OIDC、`id_token`、discovery、JWKS 或 `refresh_token`。
- 不实现跨系统单点登出。
- 不改 `bpmt-api` 对外业务接口。
- 不新增 `userid + thirdpartKey` 独立权限校验 API。
- 不重构既有微信菜单、微信 URL 或 H5 业务视图体系。
- 不在日志中记录 OAuth code、微信 code、access token、client secret 或用户密码明文。

## 3. 设计约束

- 保持 Java 8、Maven 3、Tomcat 7、MariaDB。
- OAuth 主流程继续完全位于 `bpmt-web/platform`。
- 第三方系统仍只需要跳转标准 `/oauth/authorize`，不需要理解 BPMT 私有 `/wx/url/*` 入口。
- 菜单第三方 URL / iframe 仍只是辅助入口，不作为 OAuth 主流程的一部分。
- 已有 BPMT 登录态时，继续复用当前用户，不强制重新走微信登录。
- 没有微信登录配置或配置关闭时，不做 UA 隐式推断，继续走普通登录页。
- 生产默认调用真实微信 SDK；fake 微信 provider 只能由测试或显式本地 smoke 配置启用。
- 所有可回跳第三方的地址必须先通过 `CM_THIRDPART.REDIRECT_URIS` 白名单校验。

## 4. 数据模型

`CM_THIRDPART` 增加以下字段：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `WECHAT_LOGIN_ENABLED` | `tinyint` | `0` | 是否启用微信生态自动登录 |
| `WECHAT_TYPE` | `varchar(20)` | `NULL` | `agent` 表示企业号/企业微信，`mp` 表示服务号 |
| `WECHAT_KEY` | `varchar(100)` | `NULL` | 企业号应用 key 或服务号 mpKey |
| `WECHAT_SCOPE` | `varchar(50)` | `NULL` | 服务号 OAuth scope，允许 `snsapi_base` 或 `snsapi_userinfo` |

兼容规则：

- 旧数据 `WECHAT_LOGIN_ENABLED` 默认为 `0`，行为完全等同 `v1.6.0`。
- `WECHAT_LOGIN_ENABLED=1` 时，`WECHAT_TYPE` 和 `WECHAT_KEY` 必填。
- `WECHAT_TYPE=mp` 时，`WECHAT_SCOPE` 为空则按 `snsapi_base` 处理。
- `WECHAT_TYPE=agent` 时忽略 `WECHAT_SCOPE`。
- `WECHAT_TYPE` 只接受 `agent` 或 `mp`，不支持自动猜测。

交付文件：

- `database/v1.6.1-wechat-oauth-thirdpart.sql`：已有数据库升级脚本。
- `database/bpmt-db.sql`：最小明文初始化库同步。
- `database/bpmt-min.sql.gz` 与 `database/bpmt.sql.gz`：正式初始化库同步。
- `platform/src/main/resources/hbm/common/CM_THIRDPART.hbm.xml`：HBM 字段映射同步。

## 5. 后台管理

`系统开发 -> 第三方系统` 表单新增“微信登录”配置区：

- 微信登录：启用/关闭。
- 微信类型：企业号 / 服务号。
- 微信配置 Key：企业号应用 key 或服务号 mpKey。
- 服务号 Scope：`snsapi_base` / `snsapi_userinfo`。

表单校验：

- 关闭微信登录时，微信类型、微信配置 Key、Scope 可以为空。
- 启用微信登录时，微信类型和微信配置 Key 必填。
- 服务号 Scope 只能选择允许值；空值按 `snsapi_base` 保存或运行时兜底。
- 企业号不展示或不要求 Scope。

列表页可展示“微信登录”摘要：

- `关闭`
- `企业号: <WECHAT_KEY>`
- `服务号: <WECHAT_KEY>`

## 6. OAuth authorize 数据流

`GET /oauth/authorize`

处理顺序：

1. 校验 `response_type=code`。
2. 通过 `client_id` 查询启用状态的 `CM_THIRDPART`。
3. 校验 `redirect_uri` 严格匹配 `CM_THIRDPART.REDIRECT_URIS`。
4. 如果当前已有 BPMT 登录态：
   - 复用当前 `SessionManager.getUser()`。
   - 校验目标第三方系统 `PRI_KEY` 权限。
   - 有权限则签发授权码并回跳第三方。
   - 无权限则复用 `v1.5.2` 无权限提示页。
5. 如果当前没有 BPMT 登录态：
   - 如果不是微信 UA，保存 `OAUTH_RETURN_URL` 并跳普通登录页。
   - 如果是微信 UA 但第三方未启用微信登录绑定，保存 `OAUTH_RETURN_URL` 并跳普通登录页。
   - 如果是微信 UA 且第三方启用微信登录绑定，进入微信登录补齐流程。

微信登录补齐流程：

1. 如果当前请求没有微信 `code`：
   - 使用当前完整 authorize URL 作为微信 OAuth 回调地址。
   - 按 `WECHAT_TYPE` 生成企业号或服务号授权地址。
   - 302 到微信授权地址。
2. 如果当前请求包含微信 `code`：
   - 按 `WECHAT_TYPE` 调用对应微信 provider 换取 BPMT 用户。
   - 写入 BPMT session。
   - 回到 authorize 主流程，继续第三方权限校验和授权码签发。

最终第三方通知方式仍是标准 OAuth Authorization Code 回调：

```text
redirect_uri?code=<opaque-code>&state=<original-state>
```

第三方系统随后继续调用 `/oauth/token` 换取 access token。

## 7. 微信登录服务边界

新增或抽取一个小边界，例如 `OAuthWechatLoginService`，避免把 `OAuthAction` 与微信 SDK 细节强耦合。

职责：

- 判断 OAuth client 是否启用微信登录绑定。
- 校验微信绑定配置完整性。
- 判断当前请求是否来自微信 UA。
- 在没有微信 `code` 时生成微信 OAuth 授权地址。
- 在收到微信 `code` 时完成 BPMT 用户登录。
- 暴露清晰结果给 `OAuthAction.authorize()`：
  - `SKIP`：不进入微信登录，继续普通登录页。
  - `REDIRECTED`：已重定向微信，当前请求结束。
  - `LOGGED_IN`：微信登录成功，authorize 可继续执行。
  - `ERROR`：配置或登录失败，显示 OAuth 错误页或安全回跳第三方。

企业号分支：

- 复用 `QyOAuth2s.defaultOAuth2s().authenticationUrl(...)` 生成授权地址。
- 复用 `QyOAuth2s.defaultOAuth2s().userInfo(code)` 获取 `userId`。
- 使用 `SessionManager.doUserLogin(request, userId)` 写入 BPMT 登录态。

服务号分支：

- 根据 `WECHAT_KEY` 查询 `WxMp` 配置。
- 复用 `MpOAuth2s.with(mpAppSetting).authenticationUrl(...)` 生成授权地址。
- 复用现有服务号 code 登录逻辑，将 openId/visitor 映射为 BPMT 用户。
- 写入 BPMT session 后继续 authorize。

## 8. 本机 fake provider 验证

本机不能真实测试微信登录，因此提供测试替身，不依赖微信公网。

建议新增微信 provider 接口，例如：

- `WechatOAuthProvider`
- `RealWechatOAuthProvider`
- `FakeWechatOAuthProvider`

生产默认：

- `RealWechatOAuthProvider` 调用现有 `QyOAuth2s`、`MpOAuth2s` 和 `WxActionAspect` 等逻辑。

测试和本地 smoke：

- 通过测试构造或显式配置启用 `FakeWechatOAuthProvider`。
- fake provider 只接受受控 code，例如：
  - `fake-admin` -> `admin`
  - `fake-user-no-pri` -> 无权限测试用户
  - `fake-invalid` -> 登录失败
- fake provider 不进入默认 Docker 生产配置，不在 README Quick Start 中启用。

必须验证的自动化链路：

1. 构造启用微信登录绑定的第三方系统。
2. 伪造 `User-Agent: MicroMessenger`。
3. 访问 `/oauth/authorize?...` 且无 BPMT session。
4. 首次请求返回微信授权重定向。
5. 带 `code=fake-admin` 回到同一个 authorize URL。
6. BPMT session 写入 `admin` 登录态。
7. authorize 继续签发 OAuth code。
8. 浏览器最终回到第三方 `redirect_uri`，保留原始 `state`。

## 9. 错误处理

- `client_id` 不存在、外部系统停用、`redirect_uri` 不可信：显示 BPMT OAuth 错误页，不回跳第三方。
- 微信 UA 但第三方未启用微信登录：走普通 BPMT 登录页。
- 第三方启用微信登录但配置缺失：显示 BPMT OAuth 错误页，提示管理员检查外部系统微信登录配置。
- `WECHAT_TYPE` 非法：显示 BPMT OAuth 错误页。
- `WECHAT_TYPE=mp` 但 `WECHAT_SCOPE` 非法：显示 BPMT OAuth 错误页。
- 微信授权失败或微信 `code` 无法换取 BPMT 用户：显示 BPMT OAuth 错误页，不在 `v1.6.1` 中新增微信失败到第三方 `access_denied` 的识别和回跳逻辑。
- 微信登录成功但用户无第三方权限：复用无权限提示页。
- 已有 BPMT 登录态但与微信用户不同：本版本优先复用已有 BPMT 登录态，不强制切换微信用户；用户可通过既有无权限提示页或退出流程切换账号。

## 11. 测试方案

### 11.1 单测

新增或扩展 `OAuthActionTest`、`OAuthServiceTest`、`ThirdpartServiceTest`：

- 非微信 UA 未登录访问 authorize，仍跳普通登录页。
- 微信 UA 未登录但第三方未启用微信登录，仍跳普通登录页。
- 微信 UA 未登录且第三方启用企业号绑定，无 code 时生成企业号授权重定向。
- 微信 UA 未登录且第三方启用服务号绑定，无 code 时生成服务号授权重定向。
- fake 企业号 code 成功后写入 BPMT session 并继续签发 OAuth code。
- fake 服务号 code 成功后写入 BPMT session 并继续签发 OAuth code。
- fake code 对应无权限用户时，显示无权限提示页。
- fake invalid code 时显示 OAuth 错误页，不泄露 code。
- 已有 BPMT 登录态时不触发微信登录 provider。
- 微信配置缺失、类型非法、scope 非法均返回稳定错误。
- `CM_THIRDPART` 新字段创建、编辑、默认值和 HBM 映射正确。

### 11.2 本机运行验收

本机 smoke 使用 fake provider 验证：

- `/` 返回 200。
- `/ueditor/` 返回 200。
- `/api/docs/` 返回 200。
- `/api/openapi.json` 返回 200。
- 标准 OAuth 已登录路径仍返回 code。
- 标准 OAuth 未登录非微信路径仍跳普通登录页。
- 微信 fake 企业号路径从 authorize 到第三方 callback 完整通过。
- 微信 fake 服务号路径从 authorize 到第三方 callback 完整通过。
- HTTPS 与非标准端口下，微信回调地址和第三方 redirect_uri 保留公开 scheme、host、port。
- `v1.5.1` issue #10 工作流待办“查看/处理”不回归。
- `v1.5.2` OAuth 无权限提示页不回归。

### 11.3 真实微信人工验收

真实微信登录只作为部署后人工验收项：

- 企业号/企业微信：配置可用 `WECHAT_TYPE=agent` 与 `WECHAT_KEY`，在微信内打开第三方 OAuth 入口，确认能自动微信登录并回跳第三方。
- 服务号：配置可用 `WECHAT_TYPE=mp`、`WECHAT_KEY`、`WECHAT_SCOPE`，在微信内打开第三方 OAuth 入口，确认能自动微信登录并回跳第三方。
- 验证用户无第三方权限时显示 BPMT 无权限提示页。
- 验证日志包含 requestId、clientId、thirdpartKey、wechatType、userId，但不包含敏感明文。

## 14. 验收标准

- 未配置微信登录绑定的第三方 OAuth 行为与 `v1.6.0` 一致。
- 配置企业号绑定后，微信 UA 未登录访问 `/oauth/authorize` 不再进入普通登录页，而是进入企业号微信 OAuth。
- 配置服务号绑定后，微信 UA 未登录访问 `/oauth/authorize` 不再进入普通登录页，而是进入服务号微信 OAuth。
- fake provider 可在本机完整验证“微信登录成功 -> BPMT session 写入 -> 第三方 OAuth code 回调”。
- 已有 BPMT 登录态访问 authorize 时继续复用当前用户，不强制微信登录。
- 微信登录成功后第三方接收的是标准 OAuth `code` 和原始 `state`。
- 敏感明文不进入日志。
- README、维护文档、升级 SQL、初始化库和 `AGENTS.md` 均与版本行为一致。
