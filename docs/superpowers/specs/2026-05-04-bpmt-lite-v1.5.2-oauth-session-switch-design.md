# bpmt-lite v1.5.2 OAuth 登录态切换设计

## 1. 背景与目标

`v1.5.2` 是基于 `v1.5.1` 的 OAuth 体验补丁。`v1.5.1` 已保留 `v1.5.0` 的外部系统 OAuth Authorization Code 能力，并修复完整库工作流待办跳转问题。

当前 OAuth 流程已经支持“第三方系统未登录，但当前浏览器已有 BPMT 登录态”时直接复用当前 BPMT 用户：`/oauth/authorize` 校验 `client_id` 和 `redirect_uri` 后，会通过 `SessionManager.checkUserLogin()` 判断 BPMT 登录态；如果已经登录，则使用 `SessionManager.getUser()` 校验第三方系统权限并签发授权码。

本版本要改善的是权限不足分支：当前登录用户没有目标第三方系统权限时，不再直接回跳第三方 `access_denied`，而是在 BPMT 内显示提示页，由用户选择是否退出当前 BPMT 账号并重新登录。

同时，README 的 OAuth 章节补充第三方 OAuth demo 项目链接：

- `https://github.com/wodenwang/bpmt-oauth-demo`

## 2. 范围

### 2.1 本版本包含

- 保持 OAuth Authorization Code 主流程不变。
- 已有 BPMT 登录态时继续复用当前登录用户，不显示登录页。
- 当前 BPMT 用户无目标第三方权限时，显示 BPMT 内部提示页。
- 提示页提供两个动作：
  - 退出当前账号并重新登录。
  - 取消并返回第三方系统。
- README 增加 OAuth demo 项目链接。
- 新增 `v1.5.2` 设计、验收和发布文档。
- 保留 `v1.5.1` 工作流待办 issue #10 修复作为回归基线。

### 2.2 本版本不包含

- 不新增 OAuth 协议端点。
- 不实现 OIDC、`id_token`、discovery、JWKS 或 `refresh_token`。
- 不实现跨系统单点登出。
- 不改 `bpmt-api`。
- 不改 `CM_THIRDPART`、`CM_THIRDPART_AUTH_CODE`、`CM_THIRDPART_ACCESS_TOKEN` 表结构。
- 不改 `clientSecret` 管理逻辑。
- 不新增可解密保存字段，不保存明文 `clientSecret`。
- 不在本仓实现 demo 项目，只在 README 链接外部 demo 仓库。

## 3. 设计约束

- 保持 Java 8、Maven 3、Tomcat 7、MariaDB。
- 继续在 `bpmt-web/platform` 内实现 OAuth 主流程。
- 不引入新前端框架，页面沿用现有 JSP、jQuery 和 BPMT 轻量样式。
- `clientSecret` 继续只在新增外部系统时展示一次；编辑时只能重置；数据库只保存 `CLIENT_SECRET_HASH`。
- 任何 OAuth 日志都不能记录明文 `code`、`access_token`、`client_secret`、`password`。
- 所有回跳第三方的 URL 必须来自已通过 `REDIRECT_URIS` 白名单校验的 `redirect_uri`。

## 4. 总体架构

改动集中在 `bpmt-web/platform`：

- `OAuthAction.authorize()`：保留现有参数校验、未登录跳登录页、已登录复用当前账号、签发 code 的主链路。
- 新的无权限提示页：当当前用户没有目标第三方系统权限时，渲染 BPMT 内部 JSP，而不是立即回跳第三方。
- 新的提示页动作处理：
  - 退出并重新登录。
  - 取消并返回第三方错误。
- README 和 release 文档同步。

`bpmt-api` 不参与本版本改动。API 文档、OpenAPI 和 HMAC 业务 API 只作为回归入口。

## 5. OAuth authorize 流程

`GET /oauth/authorize`

处理逻辑：

1. 校验 `response_type=code`。
2. 通过 `client_id` 查询启用状态的 `CM_THIRDPART`。
3. 校验 `redirect_uri` 是否严格匹配 `CM_THIRDPART.REDIRECT_URIS`。
4. 如果当前浏览器没有 BPMT 登录态：
   - 将完整 authorize URL 写入 `OAuthSessionKeys.RETURN_URL`。
   - 跳转 `login.jsp`。
   - 登录成功后回到原 authorize 请求。
5. 如果当前浏览器已有 BPMT 登录态：
   - 取当前 `SessionManager.getUser()`。
   - 校验当前用户是否拥有目标 `CM_THIRDPART.PRI_KEY` 权限。
6. 如果有权限：
   - 写入 `CM_THIRDPART_AUTH_CODE`。
   - 302 回跳 `redirect_uri?code=opaque-code&state=original-state`。
7. 如果无权限：
   - 保存已校验的 OAuth 上下文到 HTTP session。
   - forward 到 BPMT 内部无权限提示页。

## 6. 无权限提示页

新增页面建议路径：

- `platform/src/main/webapp/xhtml/oauth/access_denied.jsp`

页面文案：

- 标题：`当前账号无权访问外部系统`
- 说明：`当前 BPMT 账号 [userid] 没有访问 [第三方系统名称] 的权限。`
- 主按钮：`退出当前账号并重新登录`
- 次按钮：`取消并返回第三方系统`

页面只展示面向用户的必要信息：

- 当前 `userid`。
- 第三方系统名称。
- 可选 requestId。

页面不得展示：

- 明文 `code`。
- 明文 `access_token`。
- 明文 `client_secret`。
- 完整内部 session payload。

## 7. 临时状态

本版本不新增数据库表或字段。无权限提示页所需上下文只保存在 HTTP session 中。

建议 session 内容包括：

- `requestId`
- 原始完整 authorize URL
- `clientId`
- `thirdpartKey`
- `thirdpartName`
- 当前 `userId`
- 已通过校验的 `redirectUri`
- `state`

该 session 内容只能由 `OAuthAction.authorize()` 在完成 `client_id` 和 `redirect_uri` 校验后写入。提示页动作处理时必须读取该上下文，不能接受前端提交的任意回跳 URL。

## 8. 提示页动作

### 8.1 退出当前账号并重新登录

动作目标：

1. 读取并校验 session 中保存的 OAuth 上下文。
2. 清理当前 BPMT 登录态。
3. 将原始完整 authorize URL 写入 `OAuthSessionKeys.RETURN_URL`。
4. 跳转 `login.jsp`。
5. 用户重新登录后，沿用现有登录后返回逻辑回到 authorize。
6. 用新登录账号重新校验目标第三方系统权限。

该动作不直接签发 code，也不直接跳第三方。

### 8.2 取消并返回第三方系统

动作目标：

1. 读取并校验 session 中保存的 OAuth 上下文。
2. 使用已验证可信的 `redirectUri` 生成错误回跳地址。
3. 回跳 `redirect_uri?error=access_denied&error_description=permission-denied&state=original-state`。
4. 不清理当前 BPMT 登录态。

如果 session 中没有合法 OAuth 上下文，则显示 BPMT OAuth 错误页，不回跳第三方。

## 9. 错误处理

- `client_id` 不存在、外部系统停用、`redirect_uri` 不可信：继续显示 BPMT OAuth 错误页，不回跳第三方。
- 当前 BPMT 用户未登录：继续显示登录页，登录后回到原始 authorize。
- 当前 BPMT 用户已登录但无目标第三方权限：显示 BPMT 内部无权限提示页。
- 用户选择取消：回跳可信第三方 `access_denied`。
- 用户选择换账号：退出当前账号并回到登录页。
- 换账号后仍无权限：再次显示无权限提示页。

## 10. 日志

OAuth 主流程继续使用 `INFO` 日志登记关键状态。

新增建议日志点：

- `permission_denied_prompt`：当前用户无第三方权限，已显示 BPMT 提示页。
- `switch_account_requested`：用户选择退出当前账号并重新登录。
- `access_denied_cancelled`：用户选择取消并返回第三方 `access_denied`。

日志字段建议保留：

- `requestId`
- `clientId`
- `thirdpartKey`
- `userId`
- `result`
- `reason`

禁止记录：

- 明文 `code`
- 明文 `access_token`
- 明文 `client_secret`
- 用户密码

## 11. 测试方案

### 11.1 单测

`OAuthActionTest` 增加覆盖：

- BPMT 已登录且有第三方权限时，仍直接签发 code，不进入登录页。
- BPMT 已登录但没有第三方权限时，不直接回跳第三方，而是 forward 到无权限提示页。
- 无权限提示页动作保存并读取的 OAuth 上下文来自后端 session。
- 取消并返回第三方时，回跳可信 `redirect_uri`，包含 `error=access_denied` 和原始 `state`。
- 退出并重新登录时，清理当前登录态，设置 `OAuthSessionKeys.RETURN_URL`，跳转 `login.jsp`。
- session 中没有合法 OAuth 上下文时，提示页动作不回跳第三方。

既有 OAuth 测试继续保留：

- token OAuth JSON。
- userinfo Bearer token。
- OAuth DirectFilter。
- OAuthSecurity。
- OAuth HBM 映射。
- OAuth 初始化 SQL。

### 11.2 运行验收

v1.5.2 验收至少覆盖：

- `/` 返回 200。
- `/ueditor/` 返回 200。
- `/api/docs/` 返回 200。
- `/api/openapi.json` 返回 200。
- `/oauth/authorize` 未登录时进入 BPMT 登录页。
- `/oauth/authorize` 已登录且有权限时回跳 code。
- `/oauth/authorize` 已登录但无权限时显示 BPMT 无权限提示页。
- 无权限提示页点击“取消并返回第三方系统”后回跳可信 `redirect_uri`，携带 `error=access_denied`。
- 无权限提示页点击“退出当前账号并重新登录”后进入 BPMT 登录页；重新登录后回到原 authorize。
- `v1.5.1` issue #10 的 `/flow/CommonFlowAction/taskList.shtml` 查看/处理链路不回归，不出现 `_ORD_ID=null`。

## 13. 发布边界

v1.5.2 发布收口时需要：

- Maven 项目版本切到 `1.5.2`。
- 默认 Web/API 镜像 tag 切到 `1.5.2`。
- `scripts/install.sh`、`scripts/run.sh`、`scripts/init-db.sh` 默认 raw/tag 切到 `v1.5.2`。
- API OpenAPI `info.version` 可同步为 `v1.5.2`，但不得新增 OAuth 端点或修改 API 路径。
- Web/API 镜像推送：
  - `ghcr.io/wodenwang/bpmt-lite:1.5.2`
  - `ghcr.io/wodenwang/bpmt-lite-api:1.5.2`
  - `latest` 同步到对应最新 digest。

## 14. 非目标确认

本版本明确不做 `clientSecret` 可查看能力。原因是当前设计只保存 hash，无法反查明文；新增可查看能力需要引入可解密字段或明文保存，超出本补丁版本边界，也会改变 v1.5.0 已确定的安全模型。
