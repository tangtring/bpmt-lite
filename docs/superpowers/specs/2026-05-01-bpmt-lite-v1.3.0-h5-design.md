# bpmt-lite v1.3.0 H5 可浏览修复设计

## 背景

`bpmt-lite` v1.2.0 已完成 Docker 化发布、数据库初始化整理、字体与日志映射修复。v1.3.0 的重点转向移动端 H5 浏览能力。

当前 H5 不是独立前端应用，而是现有 Java Action/JSP 渲染体系的一部分：

- `ActionMode(Mode.FIT)` 根据移动 UA 或 `_action_mode=h5` 分流到 `/h5/**` JSP。
- 登录、动态表、流程、报表等 H5 页面仍依赖现有 JSP、JSTL、自定义 tag、`Wxui`、表单提交和 JSON 返回。
- H5 页面大量使用 AmazeUI class，`include/h5_head.jsp` 仍直接引用外部 CDN 资源。

用户反馈当前 H5 方式存在多个 bug，移动端连首页和登录页都无法进入。v1.3.0 必须先恢复可进入和可浏览，再逐步处理 UI 框架债务。

## 目标

v1.3.0 定位为 H5 可浏览修复版本，不是完整移动端重写版本。

本版本目标：

1. 移动端可打开登录页。
2. `admin/admin` 可在移动端完成登录。
3. 登录后移动端可进入首页、看到菜单和首页面板。
4. 流程、动态表、报表至少能完成列表和详情浏览。
5. 选择少量高频操作做冒烟验证：
   - 动态表单基础字段填写并保存。
   - 流程待办详情填写意见并提交普通流转动作。
6. H5 页面不依赖外部 CDN 才能工作。
7. 建立本地 `bpmt-h5` 轻量组件层，作为后续替换 AmazeUI 的落点。

## 非目标

v1.3.0 不做以下事情：

- 不升级 Java、Maven、Tomcat、Spring、Hibernate 等技术栈。
- 不把 H5 改造成 SPA。
- 不引入 Node、npm、Webpack、Vite 等前端构建链。
- 不引入 Vant、Framework7 等大型现代移动 UI 框架作为 v1.3.0 主方案。
- 不移动化所有后台管理页。
- 不移动化流程设计器、动态视图设计器等复杂配置工具。
- 不一次性删除 AmazeUI。
- 不重写业务功能或改变权限、菜单、流程、动态表的数据模型。

## 总体策略

v1.3.0 采用两段式策略。

### 第一段：A 方式止血

先修复 H5 登录、首页、菜单、基础浏览链路，让移动端可以进入系统并完成最小浏览闭环。

重点处理：

- H5 路由是否进入 `/h5/**` JSP。
- 登录页是否能加载全部必要资源。
- 登录提交是否正常返回 JSON 并完成跳转。
- 登录后 `/` 是否能进入移动端首页。
- 首页、菜单、面板页面是否仍引用桌面端假设。
- H5 静态资源是否依赖外部 HTTP/CDN。
- 非微信浏览器中 `wx`、`jWeixin` 等对象缺失时是否会中断页面。

### 第二段：B 方式完成 v1.3.0

在不改变服务端渲染架构的前提下，建立本地 `bpmt-h5` 轻量组件层。

该组件层不是独立前端应用，而是 JSP 可直接使用的一组本地 CSS/JS：

- `platform/src/main/webapp/h5/assets/bpmt-h5.css`
- `platform/src/main/webapp/h5/assets/bpmt-h5.js`
- 必要的本地第三方兼容资源放在 `platform/src/main/webapp/h5/vendor/**`

旧页面可以继续保留 AmazeUI class。v1.3.0 新修复或重点覆盖页面优先使用 `bpmt-h5` class 和 JS API，避免继续把页面强绑定到 AmazeUI。

## 架构设计

后端与渲染方式保持不变：

- Java 8 不变。
- Maven 3 不变。
- Tomcat 7 不变。
- JSP/FTL 服务端渲染不变。
- `ActionMode(Mode.FIT)` 和 `_action_mode=h5` 分流机制不变。
- `platform/src/main/webapp/h5/**` 继续作为 H5 页面目录。

H5 资源加载调整为本地优先：

1. `include/h5_head.jsp` 加载本地基础资源。
2. `bpmt-h5.css` 提供 v1.3.0 必要布局、列表、卡片、表单、提示样式。
3. `bpmt-h5.js` 提供兼容初始化和通用交互。
4. `Wxui` 现有调用保留，但要保证在非微信环境和外部资源不可用时可降级。
5. AmazeUI/WeUI 旧分支保留为兼容路径，不作为新页面的强依赖。

## 组件设计

`bpmt-h5` 第一版只封装 v1.3.0 需要的最小集合。

### 页面骨架

- 顶部栏。
- 页面标题。
- 页面内容容器。
- 底部版权区域。
- 移动端安全宽度、边距、字号、点击区域。

### 登录

- Logo 区域。
- 用户名输入。
- 密码输入。
- 验证码区域。
- 登录按钮。
- 错误提示。
- 加载状态。

登录页必须在普通手机浏览器、微信内置浏览器、桌面移动视口中都能打开和提交。

### 首页与菜单

- 首页面板卡片。
- 菜单列表。
- 空菜单提示。
- 无权限提示。
- 入口链接保持原有 Action URL，不改变权限和数据模型。

### 列表与详情

- 列表条目。
- 详情字段。
- 空状态。
- 错误状态。
- 分页区域。

适用范围为流程、动态表、报表的核心浏览路径。

### 表单与操作反馈

- 文本输入。
- 下拉/单选/多选的兼容展示。
- 日期字段的基础输入或降级输入。
- 保存按钮。
- 删除/提交确认。
- 成功/失败提示。
- 加载遮罩。

v1.3.0 不要求完成所有复杂控件移动端重构，只保证选定冒烟路径可操作。

## 请求与数据流

H5 请求链路保持当前模型：

1. 移动 UA 或 URL 参数 `_action_mode=h5` 进入 Action。
2. `Actions.Util.getPagePath()` 选择 `/h5/**` JSP。
3. JSP 读取 request attribute、tag 输出和后端配置。
4. 页面通过现有 form/JSON 接口提交。
5. 成功后通过原有跳转或刷新策略进入下一页。

需要保留强制模式参数：

- `_action_mode=h5`：强制使用 H5 页面，便于验证。
- `_action_mode=xhtml`：强制使用桌面页面，便于回归。

## 兼容与降级

### User-Agent 识别

`Actions.isMobile()` 需要具备防御性：

- 空 UA 不应抛异常。
- 长度小于 4 的 UA 不应因 `substring(0, 4)` 抛异常。
- `_action_mode=h5/xhtml` 优先级高于 UA 自动识别。

### 外部资源

H5 主路径不得依赖以下外部资源才能工作：

- `http://apps.bdimg.com`
- `http://cdn.bootcss.com`
- `https://cdn.bootcdn.net`
- `http://res.wx.qq.com`

微信 JS SDK 如仍需保留，应只作为增强能力。资源不可用或非微信环境下，登录、浏览、表单提交、关闭按钮不能因为 `wx` 对象不存在而失败。

### AmazeUI

AmazeUI 在 v1.3.0 保留兼容，不作为新方案继续扩大依赖。

策略：

- 旧页面上的 `am-*` class 可以继续存在。
- `bpmt-h5.css` 可以覆盖必要样式。
- 新修复页面优先写 `bpmt-h5` class。
- 后续版本再决定是否彻底移除 AmazeUI。

## 验收范围

### 必达范围 B

v1.3.0 至少保证以下路径在移动端正常浏览：

- `/login.jsp?_action_mode=h5` 返回 200。
- 登录页关键 CSS/JS 返回 200。
- 登录页无关键 JS 错误。
- `admin/admin` 登录成功。
- 登录后 `/` 在移动视口可看到首页。
- 首页菜单可打开。
- 首页面板可浏览。
- 流程列表可浏览。
- 流程详情可浏览。
- 动态表列表可浏览。
- 动态表详情可浏览。
- 报表列表可浏览。
- 报表详情可浏览。

### C 级冒烟路径

v1.3.0 只选择两条高频操作路径做冒烟：

1. 动态表单基础保存：
   - 从列表进入表单。
   - 填写基础文本、下拉、日期字段。
   - 提交保存。
   - 页面显示成功或可返回详情看到结果。
2. 流程待办普通流转：
   - 进入待办详情。
   - 填写意见。
   - 点击普通流转动作。
   - 页面显示成功或待办状态变化。

## 验证计划

每次 v1.3.0 收口至少执行：

```bash
scripts/verify-repo.sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-1.8.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
mvn -s settings.local.xml -DskipTests compile
docker compose config
```

Docker 运行验证：

- 使用完整库或最小库启动。
- 桌面 baseline：
  - `/` 返回 200。
  - `/ueditor/` 返回 200。
- H5 baseline：
  - `/login.jsp?_action_mode=h5` 返回 200。
  - 登录页全部本地关键资源返回 200。
  - `admin/admin` 可登录。
  - 登录后移动视口首页可见。
  - 流程、动态表、报表列表/详情可浏览。
  - 两条 C 级冒烟路径通过。

浏览器验证应使用移动视口，并记录：

- 请求 URL。
- HTTP 状态。
- 控制台关键错误。
- 验收截图或文字记录。

## 风险

1. H5 页面数量多，历史模板不一致。v1.3.0 必须坚持先覆盖核心浏览路径。
2. 动态表和流程页面依赖数据库配置，验收数据需要固定。
3. 老页面可能同时依赖 jQuery、AmazeUI、WeUI、微信 JS。资源本地化时要先保主路径，再清理冗余。
4. 非微信环境中旧代码可能直接调用 `wx.closeWindow()`。需要统一降级处理。
5. 旧 CSS 全局 reset 可能影响新组件层。`bpmt-h5` 样式需要尽量限定作用范围。

## 决策记录

- v1.3.0 先采用 A 方式止血。
- v1.3.0 后续使用 B 方案完成版本主体。
- v1.3.0 至少保证 B 级核心只读可浏览范围。
- C 级只选择动态表单基础保存和流程待办普通流转两条高频路径冒烟。
- 不在 v1.3.0 引入大型现代移动 UI 框架或前端构建链。
