# bpmt-lite v1.4.0 API 接口层设计

## 背景

`bpmt-lite` 当前版本为 `v1.3.0`，已完成 Docker 化发布、完整库和最小库初始化、H5 保守止血修复。`v1.4.0` 的重点是新增一套面向 BPMT 的 API 接口层，优先服务 AI agent、飞书集成平台、N8N 等外部系统。

本版本只关注动态表结构管理。动态表结构变更不仅执行 DDL，还会写入 `TB_TABLE`、`TB_COLUMN`、`TB_INDEX`、`TB_INDEX_COLUMN` 等平台元数据表，并且会影响 Web 容器中的 Hibernate 二级缓存。因此 API 设计必须同时处理认证、技术用户、缓存一致性、文档发布和测试门禁。

## 目标

1. 新增独立 `api` 子项目，提供 REST 风格 API。
2. 使用主流、简单且足够安全的 HMAC-SHA256 签名认证。
3. 使用固定技术用户执行 API 写操作，保持 BPMT 现有 `SessionManager` 语义。
4. 公开发布 OpenAPI JSON 和 Web 文档页，便于人类和 AI 阅读。
5. 首批只实现动态表结构管理 API。
6. 不关闭 Hibernate cache，不新增独立 Hazelcast 容器。
7. `web` 和 `api` 两个容器各自内嵌 Hazelcast member，通过 Docker Compose 网络组成同一缓存集群。
8. 每个对外发布接口必须有单测。

## 非目标

- 不做动态表业务数据 CRUD。
- 不开放删除动态表接口。
- 不做批量业务数据导入、导出 API。
- 不升级 Java、Maven、Tomcat、Spring、Hibernate。
- 不重写 `platform` 模块中的动态表业务逻辑。
- 不引入 OAuth2/OIDC 服务端。
- 不引入 Redis 或独立 Hazelcast Server 作为本版本必需依赖。

## 总体架构

采用独立 `api` WAR + 独立 Docker 服务方案。

新增 Maven 子模块：

```text
api/
```

`api` 模块依赖：

- `platform`
- `util`
- `dbtools`

`api` 产物：

```text
api.war
```

运行服务：

| 服务 | 作用 | 默认地址 |
| --- | --- | --- |
| `web` | 现有 BPMT Web UI，`ROOT` + `/ueditor` | `http://127.0.0.1:8080/` |
| `api` | 新增 API 服务，部署 `api.war` | `http://127.0.0.1:8081/api/` |
| `mariadb` | 共用业务数据库 | compose 内部访问 |

镜像建议：

| 镜像 | 用途 |
| --- | --- |
| `ghcr.io/wodenwang/bpmt-lite:1.4.0` | Web UI |
| `ghcr.io/wodenwang/bpmt-lite-api:1.4.0` | API 服务 |

`platform` 源码原则上不改。API 的动态表结构写操作必须通过 `TableService`、`TbTable`、`TbColumn`、`TbIndex` 等现有对象完成，不能绕过服务直接写平台元数据表。

## 部署与配置

`api` 容器和 `web` 容器使用同一套数据库连接配置：

- `DB_HOST`
- `DB_PORT`
- `DB_NAME`
- `DB_USER`
- `DB_PASSWORD`

API 认证和技术用户配置：

- `BPMT_API_APP_KEY`
- `BPMT_API_APP_SECRET`
- `BPMT_API_ACT_AS`

`BPMT_API_ACT_AS` 缺失或对应用户不存在时，兜底使用 `admin`。

`web` 和 `api` 的 Hazelcast 组网配置：

```yaml
HIBERNATE_CACHE: "true"
HAZELCAST_TCPIP: "true"
HAZELCAST_TCPIP_MEMBERS: "web,api"
HAZELCAST_GROUP_NAME: "bpmt"
HAZELCAST_GROUP_PASSWORD: "${BPMT_HAZELCAST_PASSWORD:-bpmt}"
```

本版本不使用单独 Hazelcast 容器。原因是当前项目已经使用 embedded Hazelcast 和 `HazelcastLocalCacheRegionFactory`，直接拆成 client/server 模式会引入额外 Hibernate region factory、依赖版本和配置风险。

## 认证规范

业务 API 使用 HMAC-SHA256 签名。文档端点公开，不要求签名。

请求 Header：

```text
X-BPMT-App-Key
X-BPMT-Timestamp
X-BPMT-Nonce
X-BPMT-Signature
```

签名字符串固定为：

```text
METHOD
PATH
QUERY
TIMESTAMP
NONCE
SHA256_HEX(BODY)
```

规则：

- `METHOD` 使用大写 HTTP 方法。
- `PATH` 使用请求路径，不包含 scheme、host、query。
- `QUERY` 使用规范化 query string；无 query 时为空字符串。
- `TIMESTAMP` 来自 `X-BPMT-Timestamp`。
- `NONCE` 来自 `X-BPMT-Nonce`。
- `BODY` 为空时使用空字节的 SHA256。
- 服务端必须校验 appKey、签名、时间窗口和 nonce。
- `appSecret` 不允许明文出现在请求 body 或 query 中。

## 技术用户上下文

API 认证通过后，服务端在当前请求线程中初始化：

- `RequestContext`
- `SessionContext`
- `VariableContext`

技术用户选择：

1. 优先使用 `BPMT_API_ACT_AS` 指定的 BPMT 用户。
2. 如果未配置或用户不存在，使用 `admin`。
3. 如果 `admin` 也不存在，请求返回 `403`。

技术用户上下文需要包含：

- `USER`
- `GROUP`
- `ROLE`
- `RELATION_SHIP`
- `PRI_GROUP`
- `PRI_POINT_LIST`
- `SUPER_PRI_FLAG`
- `DATE`
- `IP`
- `LOG`

目标是让 `TableService.executeCreateTable()` 中的 `SessionManager.getUser().getUid()` 等现有调用保持正常，创建人、权限语义和审计信息可以稳定落库。

## API 范围

资源模型以 `dynamic-tables` 为核心。

### 动态表结构接口

| 方法 | 路径 | 说明 | 风险 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/dynamic-tables` | 分页查询动态表结构列表 | 低 |
| `GET` | `/api/v1/dynamic-tables/{name}` | 读取表结构详情，包含字段和索引 | 低 |
| `POST` | `/api/v1/dynamic-tables` | 创建动态表，写元数据并执行建表 DDL | 高 |
| `PUT` | `/api/v1/dynamic-tables/{name}` | 调整表结构，写元数据并执行 DDL | 高 |
| `POST` | `/api/v1/dynamic-tables/{name}/sync-ddl` | 按当前元数据同步数据库结构 | 高 |
| `GET` | `/api/v1/dynamic-tables/{name}/indexes` | 读取索引配置 | 低 |
| `PUT` | `/api/v1/dynamic-tables/{name}/indexes` | 调整索引配置并执行 DDL | 高 |

### 动态表模板接口

| 方法 | 路径 | 说明 | 风险 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/dynamic-table-templates` | 列出内置动态表模板 | 低 |
| `POST` | `/api/v1/dynamic-table-templates/{templateName}/preview` | 预览模板解析结果，不写库 | 低 |
| `POST` | `/api/v1/dynamic-tables:from-template` | 按模板创建动态表 | 高 |

### 明确不开放

- `DELETE /api/v1/dynamic-tables/{name}`
- 任意动态表业务数据新增、修改、删除、查询 API
- 批量导入业务数据 API
- 导出业务数据 API

## 动态表请求模型

动态表创建和调整请求应使用清晰 JSON，避免直接暴露页面表单字段结构。

表级字段：

- `name`
- `description`
- `cacheFlag`
- `columns`
- `indexes`

字段级字段：

- `name`
- `description`
- `type`
- `totalSize`
- `scale`
- `primaryKey`
- `autoIncrement`
- `required`
- `defaultValue`
- `memo`

`type` 使用可读枚举，映射到 `com.riversoft.platform.db.Types`：

- `String`
- `Integer`
- `BigDecimal`
- `Date`
- `Long`
- `Clob`
- `Blob`

服务端负责转换为 `mappedTypeCode` 和 `TbColumn`。

基本校验：

- 表名不能为空。
- 表名不能以系统表前缀开头，例如 `CM_`、`DEV_`、`VW_`、`WDG_`、`ACT_GE_`、`ACT_RE_`、`US_`、`WF_`、`TB_`、`TPL_`、`WX_`。
- 字段列表不能为空。
- 必须至少有一个主键。
- 字段名在同一表内不能重复。
- 索引名在同一表内不能重复。
- 索引字段必须来自当前表字段列表。
- 不允许通过 API 删除表。

## 错误模型

所有 API 错误统一返回 JSON：

```json
{
  "success": false,
  "error": {
    "code": "DYNAMIC_TABLE_ALREADY_EXISTS",
    "message": "表[XXX]已存在。",
    "details": {},
    "requestId": "..."
  }
}
```

HTTP 状态：

| 状态 | 场景 |
| --- | --- |
| `400` | 请求 JSON、字段类型或必填参数错误 |
| `401` | 缺少认证信息、appKey 不存在或签名错误 |
| `403` | 认证通过但技术用户不可用或权限不足 |
| `404` | 动态表或模板不存在 |
| `409` | 表已存在、字段冲突、索引冲突 |
| `422` | 动态表规则校验或 DDL 执行失败 |
| `500` | 未预期系统异常 |

错误码必须稳定，便于 AI agent 判断是否重试、修正请求或停止操作。

## OpenAPI 与 Web 文档

文档公开发布：

- `GET /api/openapi.json`
- `GET /api/docs/`

文档端点不需要 HMAC 认证。业务 API 必须认证。
当前实现采用不依赖外部 CDN 和 WebJar 的静态 `docs/index.html`，直接读取同应用内的 `openapi.json`。

OpenAPI 每个对外接口必须包含：

- `summary`
- `description`
- 请求 JSON Schema
- 响应 JSON Schema
- 错误码列表
- HMAC 签名说明
- `curl` 示例
- `x-bpmt-writes-metadata`
- `x-bpmt-executes-ddl`
- `x-bpmt-risk-level`

风险扩展字段约定：

```yaml
x-bpmt-writes-metadata: true
x-bpmt-executes-ddl: true
x-bpmt-risk-level: high
```

文档中必须明确说明：

- 动态表结构写接口会修改数据库结构。
- 动态表结构写接口会写 BPMT 元数据表。
- 本版本不支持删除表。
- 本版本不支持动态表业务数据 CRUD。

## 缓存一致性

v1.4.0 不能关闭 Hibernate cache。

缓存策略：

1. `web` 和 `api` 均保留 `HIBERNATE_CACHE=true`。
2. 两个容器各自内嵌 Hazelcast member。
3. Docker Compose 中启用 Hazelcast TCP/IP join。
4. 两个 member 使用同一 group name 和 password。
5. API 写结构必须走 Hibernate 管理的 `TableService`，不能直接 JDBC 写元数据表。

验收重点：

1. 启动 `web + api + mariadb`。
2. 先从 `web` 读取目标动态表结构，让 Web 侧产生缓存。
3. 通过 `api` 创建或调整动态表结构。
4. 不重启 `web`。
5. 再次从 `web` 动态表管理页或业务视图读取结构。
6. 验证新字段、新索引或新表可见。
7. 验证 DDL 已落到 MariaDB。
8. 验证 `web` 和 `api` 日志中 Hazelcast 已加入同一集群。

如果 Hazelcast 双 member 验证失败，发布 fallback 是收缩写接口发布范围，而不是关闭缓存。即 API 服务可以保留文档和读接口，但结构写接口不得默认开启。

## 测试策略

每个对外发布接口都必须完成单测。

测试分层：

| 层级 | 目标 |
| --- | --- |
| Controller 或 Servlet 单测 | 路由、JSON 解析、认证失败、错误响应结构 |
| Schema 和 Validator 单测 | 表名、字段名、字段类型、主键要求、索引规则、危险能力不暴露 |
| Service 单测 | `TbTable`、`TbColumn`、`TbIndex` 构造、模板预览、技术用户兜底、错误码映射 |
| 集成验收 | API 写结构后 Web 侧无重启读取，确认 Hazelcast cache 一致 |

发布 gate：

```bash
scripts/verify-repo.sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-1.8.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
mvn -s settings.local.xml -DskipTests compile
mvn -s settings.local.xml -pl api -am -Dtest=ApiDocsContractTest,ApiServletTest,DynamicTableControllerTest,DynamicTableServiceTest,DynamicTableValidatorTest,HmacSignatureTest,ApiUserContextTest -DfailIfNoTests=false test
docker compose config
scripts/build-image.sh
scripts/build-api-image.sh
```

API smoke 脚本必须覆盖：

- `/api/openapi.json` 公开返回 200。
- `/api/docs/` 公开返回 200。
- 无签名访问业务接口返回 401。
- 正确签名可访问读接口。
- 正确签名可创建测试动态表。
- Web 侧不重启可读到新结构。
