# bpmt-lite v1.7.0 动态表视图 API 设计

## 版本定位

`v1.7.0` 是面向外部 AI agent 的动态表视图配置 API 版本。最大目标是把现有 `dyn` 动态表视图从“只能通过后台前端页面配置”推进到“可以通过公开 API 完整创建、导出、校验、更新和删除”。

本版本只覆盖 `viewClass=dyn` 的动态表视图配置，即 `VW_URL` 与 `VW_DYN_*` 这一套模型。`dyn` 本身已经覆盖主表绑定、字段、控件、查询条件、数据筛选、变量、处理器、子表、按钮、微信/H5 和页面脚本，足够作为独立版本交付。

## 范围与非范围

### 本版本范围

- 新增 `dynamic_table_views` API 模块。
- 对外开放 `dyn` 动态表视图的完整配置快照。
- 支持从零创建视图。
- 支持导出现有视图快照，并保证导出的 JSON 可以作为 `PUT` 回写基线。
- 支持全量替换视图配置。
- 支持按区块替换局部配置。
- 支持独立 `validate` 预检。
- 支持 `dryRun=true` 走真实写入路径演练但不写库。
- 支持删除 `dyn` 视图配置，删除必须带确认参数。
- 自动生成、保留和回填权限资源。
- 允许提交脚本字段，并返回风险提示。

### 明确非范围

- 不覆盖 `flowbasic`、`rep_list`、`note`、`viewer` 等其他动态视图模块。
- 不创建或修改动态表结构。动态表结构继续通过现有 `/api/v1/dynamic-tables` API 管理。
- 不管理动态表业务数据 CRUD。
- 不创建菜单、首页、按钮入口或其他发布入口。
- 不执行脚本沙箱验证，不承诺脚本语义正确。
- 不删除动态表结构、业务数据或业务日志数据。
- 不升级 Java、Tomcat、MariaDB、Maven 或前端技术栈。

## 现有链路摘要

当前后台前端配置链路如下：

1. `ViewConfigAction.submit()` 处理 `viewClass`、`loginType`、`description` 等门面字段。
2. `ViewConfigService.executeSaveConfig()` 或 `executeUpdateConfig()` 写入 `VW_URL`。
3. `ViewConfigService` 根据 `viewClass=dyn` 找到 `DynViewAction`。
4. `DynViewAction.saveConfig()` 或 `updateConfig()` 构造 `DynDataBuilder`。
5. `DynDataBuilder` 从 `RequestContext` 中读取 `table.*` 参数，写入 `VW_DYN_TABLE`。
6. `BaseDataBuilder.handleConfig()` 扫描并执行 `ColumnsHandler`、`BtnsHandler`、`QuerysHandler`、`LimitsHandler`、`ExecsHandler`、`VarsHandler`、`SubsHandler`、`WeixinHandler`、`JsHandler`、`FrameSettingHandler`。
7. 各 handler 从页面动态生成的 request 参数中拼出 `VW_DYN_*` 子配置和 `CmPri` 权限资源。

v1.7.0 不能继续依赖这个 request 参数协议。新 API 需要把这一套页面驱动逻辑沉淀为可直接接收 JSON 快照的服务层。

## 总体架构

新增 `api/src/main/java/com/riversoft/api/modules/dynamic_table_views/` 模块，继续挂在现有独立 `api` 子项目下。

对外路径统一为：

```text
/api/v1/dynamic-table-views
```

模块沿用现有 API 基线：

- HMAC-SHA256 鉴权。
- `BPMT_API_ACT_AS` 技术用户上下文。
- `success/data/error` JSON 包装。
- 稳定错误码与 `requestId`。
- `/api/openapi.json` 和 `/api/docs/` 文档出口。

核心新增服务：

```text
DynViewConfigService
```

该服务负责：

- 快照读取：从 `VW_URL` 与 `VW_DYN_*` 还原语义化 JSON。
- 快照校验：校验结构、引用、权限、脚本风险和运行兼容性。
- 快照写入：把语义化 JSON 写回 `VW_URL`、`VW_DYN_*`、`CmPri`。
- 区块合成：把 `PATCH` 的区块内容覆盖到当前完整快照上。
- 写入计划：为 `dryRun` 和真实写入生成统一计划。
- 缓存处理：写入后刷新或失效相关 Hibernate 二级缓存。

## 接口设计

### 接口清单

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| `GET` | `/api/v1/dynamic-table-views` | 分页查询 `dyn` 视图摘要列表 |
| `POST` | `/api/v1/dynamic-table-views` | 创建 `dyn` 视图, body 为完整快照, 可带 `dryRun=true` |
| `GET` | `/api/v1/dynamic-table-views/{viewKey}` | 导出完整快照 |
| `PUT` | `/api/v1/dynamic-table-views/{viewKey}` | 全量替换视图配置, 可带 `dryRun=true` |
| `PATCH` | `/api/v1/dynamic-table-views/{viewKey}/{section}` | 替换单个配置区块, 可带 `dryRun=true` |
| `DELETE` | `/api/v1/dynamic-table-views/{viewKey}?confirmViewKey={viewKey}` | 删除视图配置 |
| `POST` | `/api/v1/dynamic-table-views:validate` | 独立预检完整快照, 不写库 |

### section 枚举

`PATCH` 首版只支持区块替换，不支持单项级增删改。

允许的 `section`：

- `base`
- `fields`
- `queries`
- `limits`
- `processors`
- `variables`
- `subviews`
- `buttons`
- `weixin`
- `scripts`

`PATCH /fields` 表示替换完整字段区块。请求中没有出现的字段视为删除。

### validate 与 dryRun

`validate` 是独立预检接口，适合 AI agent 在生成配置阶段校验完整快照。它不要求目标视图一定已经存在，但如果传入 `viewKey` 并且该视图存在，应结合现有权限资源和引用做更精确校验。

`dryRun=true` 用于 `POST`、`PUT`、`PATCH`。它必须走真实写入前的同一条校验和计划生成路径，返回将要写入、更新、删除的底层配置摘要，但不写任何表。

### 顶层字段

| 快照字段 | 底层映射 | 说明 |
| --- | --- | --- |
| `viewKey` | `VW_URL.VIEW_KEY`, `VW_DYN_*.VIEW_KEY` | 创建时可不传, 由服务端生成；也可传入合法且唯一的稳定 key |
| `description` | `VW_URL.DESCRIPTION`, `VW_DYN_TABLE.DESCRIPTION` | 视图说明 |
| `loginRequired` | `VW_URL.LOGIN_TYPE` | `true` 映射系统用户登录, `false` 映射无需登录 |
| `base` | `VW_DYN_TABLE` | 绑定表与主配置 |
| `fields` | `VW_DYN_COLUMN*` | 列表、详情、表单、分割线配置 |
| `queries` | `VW_DYN_QUERY*` | 普通查询与高级查询 |
| `limits` | `VW_DYN_LIMIT` | 数据筛选规则 |
| `variables` | `VW_DYN_EXEC_PREPARE`, `VW_DYN_PARENT*` | 展示变量与父表变量 |
| `processors` | `VW_DYN_EXEC_BEFORE`, `VW_DYN_EXEC_AFTER` | 前后置处理器 |
| `subviews` | `VW_DYN_SUB_SYS`, `VW_DYN_SUB_VIEW` | 系统标签与视图子标签 |
| `buttons` | `VW_DYN_BTN_SYS`, `VW_DYN_BTN_ITEM`, `VW_DYN_BTN_SUMMARY` | 系统按钮、自定义明细按钮、自定义汇总按钮 |
| `weixin` | `VW_DYN_WEIXIN` | 微信/H5 展示配置 |
| `scripts` | `VW_DYN_TABLE.LIST_JS_*`, `FORM_JS_*` | 页面 JS |

### base

```json
{
  "tableName": "CRM_CUSTOMER",
  "displayName": "客户资料",
  "logTableName": "CRM_CUSTOMER_LOG",
  "layoutColumns": 2,
  "initQuery": true,
  "pageLimit": 20,
  "defaultSort": {
    "field": "CREATE_DATE",
    "direction": "desc"
  }
}
```

规则：

- `tableName` 必须指向已有动态表元数据 `TbTable`。
- `logTableName` 可为空；不为空时必须符合现有候选日志表规则：与主表主键名称和类型一致，且不是主表自身。
- `layoutColumns` 范围为 `1` 到 `5`。
- `initQuery=true` 映射 `INIT_QUERY=1`。
- `defaultSort.field` 必须是主表字段或可排序展示字段。
- `direction` 只允许 `asc` 或 `desc`。

### fields

```json
{
  "systemFields": [
    {
      "name": "CUSTOMER_ID",
      "displayName": "客户ID",
      "showInDetail": true,
      "showInForm": true,
      "showInList": true,
      "widget": "text{required:true}",
      "content": {
        "type": 1,
        "script": "return cm.widget('text', vo?.CUSTOMER_ID);"
      },
      "widgetParam": null,
      "widgetContent": null,
      "tip": null,
      "style": null,
      "wholeLine": false,
      "beforeSave": null,
      "permissions": {
        "view": null,
        "create": null,
        "update": null
      }
    }
  ],
  "computedFields": [],
  "formFields": [],
  "sectionLines": [],
  "listOrder": ["CUSTOMER_ID"]
}
```

映射规则：

- `systemFields` 映射 `VW_DYN_COLUMN`。
- `computedFields` 映射 `VW_DYN_COLUMN_SHOW`。
- `formFields` 映射 `VW_DYN_COLUMN_FORM`。
- `sectionLines` 映射 `VW_DYN_COLUMN_LINE`。
- `listOrder` 不单独落表, 写入 `VW_DYN_COLUMN.LIST_SORT` 和 `VW_DYN_COLUMN_SHOW.LIST_SORT`。
- `wholeLine=true` 映射 `WHOLE=1`。
- `content.type`、`widgetParam.type`、`widgetContent.type`、`tip.type`、`beforeSave.type` 沿用现有脚本类型枚举值。

系统字段可由服务端自动补齐默认值。默认规则沿用现有 `ColumnsHandler` 行为：

- `Date` 字段默认 `date` 控件。
- `Clob` 或大长度字符串默认 `textarea` 并占整行。
- `Blob` 默认文件控件。
- 其他字段默认 `text`。
- 主键或必填字段默认追加必填校验。
- 整数和长整数默认追加 `digits:true`。
- 数值字段默认追加 `number:true`。

### variables

```json
{
  "prepared": [
    {
      "key": "currentDept",
      "var": "dept",
      "description": "当前部门",
      "exec": {
        "type": 1,
        "script": "return SessionManager.getUser().getGroupId();"
      }
    }
  ],
  "parents": [
    {
      "key": "customerType",
      "tableName": "CRM_CUSTOMER_TYPE",

      "description": "客户类型",

          "mainColumn": "TYPE_ID",

```

`prepared` 映射 `VW_DYN_EXEC_PREPARE`。`parents` 映射 `VW_DYN_PARENT` 与 `VW_DYN_PARENT_FOREIGN`。

- `parents.var` 不能为 `vo`。
- 父表必须存在。
- 外键字段必须分别存在于主表和父表。
- 每个父表至少需要一个外键。

## 权限资源设计

API 自动生成和维护 `CmPri`，外部 agent 可以不传 `priKey`。

### 权限保留规则

`PUT` 全量替换或 `PATCH` 区块替换时，服务端尽量保留旧权限资源。

稳定匹配键：

- 系统字段：`systemField:<name>`
- 展示字段：优先 `computedField:<key>`，无 `key` 时退化为同区块顺序。
- 表单字段：优先 `formField:<key>`。
- 分割线：优先 `sectionLine:<key>`。
- 普通查询：优先 `normalQuery:<key>`。
- 高级查询：优先 `advancedQuery:<key>`。
- 数据限制：优先 `limit:<key>`。
- 处理器：优先 `processor:<before|after>:<key>`。
- 展示变量：优先 `preparedVariable:<key>`。
- 父表变量：优先 `parentVariable:<key>`。
- 系统标签：`systemTab:<name>`。
- 视图标签：优先 `viewTab:<key>`。
- 系统按钮：`systemButton:<name>:<type>`。
- 自定义按钮：优先 `itemButton:<key>` 或 `summaryButton:<key>`。
- 微信配置：`weixin`.

没有 `key` 的配置项，服务端可以生成稳定 `key` 并在响应快照中返回。AI agent 后续应保留这些 `key`，避免无意义地重建权限资源。

### 删除规则

删除配置项时，服务端删除或解除该配置关联的权限资源：

- 如果权限资源只被该配置独占，删除 `CmPri`。
- 如果后续发现权限资源有共享关系，只解除当前配置关联，不删除共享资源。
- 删除整个视图时，删除当前 `viewKey` 下所有动态视图独占权限资源。

## 脚本风险设计

允许提交以下脚本字段：

- 字段内容脚本。
- 字段控件参数脚本。
- 字段控件值脚本。
- 字段提示脚本。
- 字段前置处理脚本。
- 查询 SQL 片段脚本。
- 数据筛选 SQL 脚本。
- 展示变量脚本。
- 前后置处理器脚本。
- 子标签动态参数脚本。
- 按钮动态参数脚本。
- 微信标题、图片、描述、日期脚本。
- 页面 JS 脚本。

### 校验边界

首版不做沙箱执行。`validate` 和 `dryRun` 只做静态检查：

- 脚本类型枚举必须合法。
- 非空要求必须满足。
- 明显危险关键字返回高风险提示。
- SQL 片段类脚本必须标记为 SQL 风险。
- 页面 JS 必须标记为前端执行风险。
- 脚本中直接引用的主表字段如能静态识别，应校验字段存在。

### 风险响应

响应中返回 `warnings`：

```json
[
  {
    "level": "HIGH",
    "path": "processors.before[0].exec.script",
    "code": "SCRIPT_RISK_MUTATION",
    "message": "前置处理器脚本可能修改业务数据, 请人工确认。"
  }
]
```

日志禁止记录完整脚本文本。只允许记录：

- `viewKey`
- 区块名
- 字段路径
- 脚本类型
- 脚本长度
- 脚本 hash
- 风险级别

## 校验规则

### 结构校验

- 顶层 JSON 必须是对象。
- `base` 必须存在。
- `base.tableName`、`base.displayName`、`base.defaultSort.field`、`base.defaultSort.direction` 必填。
- `fields.systemFields` 至少应包含一个可展示或可表单字段。
- 所有数组排序由服务端按数组顺序写入 `sort`。
- `listOrder` 中的字段必须存在于 `systemFields` 或 `computedFields`。
- 脚本对象如果存在，必须同时包含合法 `type` 和非空 `script`，除非该字段允许为空。

### 引用校验

- `base.tableName` 必须存在于 `TbTable`。
- `systemFields.name` 必须存在于绑定动态表。
- `base.defaultSort.field` 必须存在于绑定动态表字段或可排序展示字段。
- `queries.normal.field` 必须存在于绑定动态表。
- 父表变量的 `tableName` 必须存在。
- 父表外键字段必须分别存在于主表和父表。
- `logTableName` 必须符合候选日志表规则。
- 系统按钮必须来自现有 `SysBtn` 枚举。
- 系统标签必须来自现有 `SysTab` 枚举。

### 运行兼容校验

- 目标快照必须能生成一个可渲染的 `VwDynTable`。
- `PATCH` 后的合成快照也必须满足完整快照校验。
- 删除和替换不能影响绑定动态表结构和业务数据。
- 对非 `dyn` 视图执行 `PUT`、`PATCH`、`DELETE` 必须拒绝。

## 写入流程

### 创建

1. 读取完整快照。
2. 如果未传 `viewKey`，服务端生成。
3. 校验 `viewKey` 唯一性。
4. 合成目标快照并补齐默认字段、默认系统按钮、权限资源。
5. 执行校验。
6. 生成写入计划。
7. `dryRun=true` 时返回计划，不写库。
8. 真实写入时开启事务，写 `VW_URL`、`VW_DYN_TABLE`、`VW_DYN_*`、`CmPri`。
9. 刷新或失效相关缓存。
10. 回读完整快照并返回。

### 全量替换

1. 通过 `{viewKey}` 加载 `VW_URL`。
2. 确认 `VIEW_CLASS=dyn`。
3. 读取请求完整快照，路径中的 `{viewKey}` 为准。
4. 匹配并保留旧权限资源。
5. 快照未出现的旧配置视为删除。
6. 执行校验、生成计划、根据 `dryRun` 决定是否写库。
7. 写入成功后回读完整快照。

### 区块替换

1. 加载现有完整快照。
2. 用请求体替换指定 `section`。
3. 对合成后的完整快照执行同一套校验。
4. 只生成该区块及其相关权限资源的写入计划。
5. 根据 `dryRun` 决定是否写库。
6. 写入成功后回读完整快照。

### 删除

只允许：

```text
DELETE /api/v1/dynamic-table-views/{viewKey}?confirmViewKey={viewKey}
```

删除内容：

- `VW_DYN_WEIXIN`
- `VW_DYN_TABLE` 及其级联配置。
- 当前视图独占的 `CmPri` 权限资源。
- `VW_URL`

不删除：

- `TB_TABLE`、`TB_COLUMN`、`TB_INDEX`、`TB_INDEX_COLUMN`
- 动态业务表。
- 动态业务数据。
- 日志表和日志数据。

## 错误码

| code | HTTP | 场景 |
| --- | --- | --- |
| `DYNAMIC_TABLE_VIEW_NOT_FOUND` | `404` | 视图不存在 |
| `DYNAMIC_TABLE_VIEW_NOT_DYN` | `409` | `viewKey` 存在但不是 `dyn` |
| `DYNAMIC_TABLE_VIEW_ALREADY_EXISTS` | `409` | 创建时 `viewKey` 冲突 |
| `DYNAMIC_TABLE_VIEW_INVALID_SNAPSHOT` | `400` | 快照结构不合法 |
| `DYNAMIC_TABLE_VIEW_TABLE_NOT_FOUND` | `404` | 绑定动态表不存在 |
| `DYNAMIC_TABLE_VIEW_FIELD_NOT_FOUND` | `422` | 引用字段不存在 |
| `DYNAMIC_TABLE_VIEW_PERMISSION_INVALID` | `422` | 权限资源无法生成或保留 |
| `DYNAMIC_TABLE_VIEW_SCRIPT_RISK` | `422` | 脚本风险超过允许级别 |
| `DYNAMIC_TABLE_VIEW_CONFIRM_REQUIRED` | `400` | 删除缺少确认参数 |
| `DYNAMIC_TABLE_VIEW_WRITE_FAILED` | `500` | 事务写入失败 |

## 回滚策略

- API 回滚：恢复到 `v1.6.2` Web/API 镜像和文档快照。
- 数据回滚：本版本不改动态表结构，不改业务数据。视图配置写入失败时事务回滚。
- 已创建的测试视图可以通过本版本删除接口或后台页面删除，删除不会影响绑定动态表。
- 如 `dynamic-table-views` 模块出现风险，可临时从 `ApiServlet` 路由中移除该模块，保留既有 `dynamic-tables` 和 `database-operations` 接口。
